# 비교 분석 — 본 프로젝트 vs 친구의 DISPLAY FIT

> 작성: 2026-07-23, 오너 부재 중 참고용 분석. **결정·구현 사항이 아니라 검토 자료**다.
> 계산 규칙/스펙 변경은 CLAUDE.md 원칙에 따라 오너(김현규) 승인 후에만 반영한다.

친구가 공유한 **DISPLAY FIT**(2026-07-22, ChatGPT/OpenAI로 제작 추정)를 본 프로젝트
**LED Wall Configurator**와 비교했다. 두 도구는 "공간 입력 → 삼성 LED 캐비닛 배열·스펙 산출"
이라는 **동일한 목적**을 갖지만, 규모·구조·범위가 크게 다르다.

---

## 1. 한눈에 보기

| 항목 | 본 프로젝트 (LED Wall Configurator) | 친구 (DISPLAY FIT) |
|---|---|---|
| 제작 방식 | Claude + AI-DLC | ChatGPT/OpenAI + AI-DLC |
| 현재 단계 | INCEPTION 후반 (프로토타입 v0.2) | CONSTRUCTION · Build & Test |
| 기술 스택 | **바닐라 JS, 빌드리스**, ESM 단일 페이지 | **Next.js 16 + React 19 + vinext**, Cloudflare Workers |
| 데이터 저장 | 없음(클라이언트) · JSON import/export | **D1(SQLite) + Drizzle ORM** |
| 외부 의존성 | **0개** | next, react, drizzle-orm, xlsx, tailwind, wrangler 등 다수 |
| 서버 | 없음 (정적) | 있음 (API 라우트 + 관리자 인증) |
| 견적/원가 | 없음 | **관리자 로그인 + 비밀 원가표(Excel) + 원가×1.8 판매가** |
| 배포 난이도 | 파일 복사/정적 호스팅 (매우 쉬움) | HTTPS + DB + 비밀 환경변수 필요 (무거움) |
| 테스트 | node:test 6종 (green) | 계산 테스트 + 서버 렌더링 + 원가 통합 테스트 |
| 강점 | 가볍고 배포 쉬움, 다모델 동시 비교표, 배열 시각 미리보기, 모델 CRUD | S-Box 자동 산출, 견적/원가, 데이터 신뢰도 3단계, 더 넓은 모델군 |

**요약:** 본 프로젝트는 "가볍고 즉시 쓰는 사내 계산·비교 도구", 친구 것은 "원가·견적까지
포함한 배포형 웹 서비스"에 가깝다. 계산 엔진의 **핵심 공식은 거의 동일**하다.

## 2. 계산 공식 비교 (거의 동일)

| 계산 | 본 프로젝트 `engine.js` | 친구 `calculator.ts` | 동일? |
|---|---|---|---|
| 열 수 | `floor(W / cabW)` | `floor(W / cabW)` | ✅ |
| 행 수 | `floor(H / cabH)` | `floor(H / cabH)` | ✅ |
| 전체 해상도 | `cols·resW × rows·resH` | `cols·pxW × rows·pxH` | ✅ |
| 대각(inch) | `√(W²+H²)/25.4` | `√(W²+H²)/0.0254` (m→inch) | ✅ (단위만 다름) |
| 발열(BTU/h) | `maxW × 3.412142` | `maxW × 3.412` | ✅ (상수 자릿수만) |
| 평균전력 | `max × 0.527` (전역 계수) | 모델별 `typicalPowerW` 저장 | ⚠ 방식 차이 |
| 예비 캐비닛 | `ceil(total × 0.10)` | `round(total × 0.10)`, 최소 1 | ⚠ 반올림 규칙 차이 |
| 무결성(null) | 값 없으면 `null`, "—" 표시 | 값 없으면 `null`, "확인 필요" 표시 | ✅ 철학 동일 |

**교차 검증 포인트(좋은 소식):** 친구의 MP008F는 `typicalPowerW 64 / maxPowerW 122 = 0.525`.
본 프로젝트의 평균전력 계수 **0.527**(MP012F 3234/6132)과 사실상 일치 → **계수 0.52~0.53
가정이 서로 다른 모델에서 독립적으로 확인됨.**

### 본 프로젝트에 없는 친구의 계산

1. **S-Box(컨트롤러) 수량 자동 산출** — 본 프로젝트 SPEC §4의 미확정 항목을 친구는 이렇게 해결:
   ```
   S-Box = ceil(전체 픽셀 / (컨트롤러 최대입력 W × H))
   이중화(redundancy) 시 × 2
   ```
   예) MP008F 4×6=24캐비닛 → 3840×3240 = 12.44M px, 컨트롤러 3840×2160 = 8.29M
   → ceil(1.5) = **2대** (이중화 시 4대). ← 친구 테스트로 검증됨.
2. **일체형 컨트롤러(integratedController)** 모델(All-in-One, Video Wall) → S-Box 0, MMF는 1×1 고정.
3. **coveragePercent**(공간 대비 실제 화면 면적 %)와 **fits**(화면 ≤ 벽) 판정.
4. **Feet/Meter 단위 변환** 입력.

## 3. 모델 데이터(카탈로그) 비교 — ⚠ 확인 필요한 불일치 있음

| 모델 | 본 프로젝트 | 친구 DISPLAY FIT | 비고 |
|---|---|---|---|
| **MP012F** | maxPower **146W**, weight 9.2, `validated:true` | maxPower **null**, `derived` | ⚠ **본 프로젝트가 삼성 도구로 직접 검증한 146W가 더 신뢰도 높음.** 친구는 파생값으로 비워둠 |
| **MP008F** | maxPower **null** | maxPower **122W**, typ 64, `verified` | ✅ 친구의 검증값으로 본 프로젝트 null을 채울 후보 |
| 명명 체계 | IW/IF/IE/MM/IB 시리즈 | MPF/MMF/IF-R/IE/Video Wall | 친구가 **All-in-One·Video Wall·Fine 캐비닛**까지 포함해 모델군이 넓음 |
| 데이터 신뢰도 | `validated: true/false` (2단계) | `verified / derived / needs-verification` (3단계) | 친구 쪽이 더 세분화 |

**핵심:** 두 카탈로그는 **서로의 빈칸을 메워줄 수 있다.** 단, MP012F 전력값은
본 프로젝트(146W, 삼성 도구 실측)가 우선한다.

## 5. 어느 쪽으로 갈지 — 선택지 (오너 결정 필요)

세 갈래가 있으며, **목표에 따라 다르다.** (이건 결정이 아니라 제안이다.)

- **A. 본 프로젝트 유지 + 좋은 아이디어만 흡수 (권장 후보)**
  가볍고 배포 쉬운 현재 구조를 지키면서, 친구의 **S-Box 산출 규칙·데이터 신뢰도 3단계·
  검증된 전력값**만 흡수. 견적/원가·DB·인증 같은 무거운 기능은 필요할 때만 후속으로.
  → 본 프로젝트의 SPEC §4 미확정 3건 중 **S-Box 규칙을 바로 확정할 근거**가 생김.

- **B. 친구 것으로 통합**
  원가·견적·관리자 기능이 사업상 반드시 필요하면 친구의 서비스형 구조 채택.
  단 HTTPS·DB·비밀 환경변수·배포 운영 부담이 크고, 원가표 보안(서버 전용) 관리 필요.

- **C. 병행**
  일선 견적 담당은 가벼운 본 프로젝트로 빠른 비교, 원가·판매가는 친구의 서버 도구로 분리.

### 만약 A로 간다면 — 구체 반영 후보 (승인 시)

1. **S-Box 규칙 확정**: 모델 스키마에 `maxInputWidth/Height` 추가 →
   `ceil(전체픽셀 / 컨트롤러용량)`, 이중화 ×2. (SPEC §4 "S-Box 대수" 해소)
2. **전력 데이터 보강**: 친구의 MP008F 검증값(122W/64W)으로 본 프로젝트 null 채움.
   *(MP012F는 본 프로젝트 146W 유지)*
3. **데이터 신뢰도 3단계** 도입: `validated:bool` → `verified/derived/needs-verification`.
4. **평균전력**: 전역 계수 0.527 유지하되, 모델별 실측 `typicalPower`가 있으면 우선 사용.
5. (범위 Q2) **일체형/Video Wall** 모델 지원 여부 검토.

## 6. 참고: 두 프로젝트의 공통 주의사항

- 둘 다 **사내 견적/설계 보조용**이며 공식 견적은 삼성/설치 파트너 확인 필요.
- 둘 다 **미확인 스펙을 가짜 숫자로 채우지 않는다**(null 처리) — 좋은 원칙, 유지할 것.
- 친구 문서 경고: 원가·관리자 비밀번호·세션 시크릿은 메신저/공개 저장소에 올리지 말 것.
  본 프로젝트도 개인정보·자격증명·가격계약 정보를 코드/문서에 넣지 않는다(CLAUDE.md 규칙).
